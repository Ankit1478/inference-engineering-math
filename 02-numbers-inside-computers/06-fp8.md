# 2.6 FP8

**FP8 stores each decimal number in 1 byte instead of 2, so the model is half the size and faster, with almost the same answers.**

## Quick summary (read this first)

1. FP8 = a **1-byte decimal** format. It's half the size of BF16.
2. Half the size means **half the memory, faster, and cheaper**.
3. It's a **tiny bit less exact**, but the answers stay **almost the same**.
4. It only runs fast on **new GPUs** (H100 and newer), not on the A100.
5. There are 2 types: **E4M3** (more exact, used for **inference** ⭐) and **E5M2** (bigger range, used for training).
6. It also uses a **scale**, the same as quantization (2.4).
7. **Always test quality** before using it.

### Sizes of each format

| Format | Size per number |
|---|---|
| FP32 | 4 bytes |
| FP16 / BF16 | 2 bytes |
| FP8 / INT8 | 1 byte |
| INT4 | ½ byte |

The size per number is exact. A whole quantized model is **a little bigger** than parameters × size (about 5–15% extra), because the scales need space and some parts stay in BF16.

### Common mistakes

| ❌ Wrong | ✅ Right |
|---|---|
| "BF16 is 4 bytes" | **BF16 is 2 bytes.** FP32 is 4 bytes. |
| "FP8 is more accurate" | **BF16 is more accurate.** FP8 is the "best deal": almost the same answers at half the cost. |
| "FP8 makes the model hallucinate" | Hallucination comes from **training**. FP8 only adds tiny errors that usually don't change the answer. |
| "FP8 works on any GPU" | It needs **H100 or newer** for the speed-up. |
| "INT16 is used for AI" | Not really. You probably mean **FP16**. |

## Why this matters for inference

- Inference engineering = **running a trained model for users, as fast and cheaply as possible**.
- FP8 is one of the easiest ways to make a model smaller, faster and cheaper.
- These formats are mainly for **deploying**. Training mostly stays in BF16 (a few exceptions: FP8 training in DeepSeek-V3, and QLoRA which fine-tunes with a 4-bit base model).

## Real-life example

### Writing a number on a card 📝

| Card | Name | Size | Example |
|---|---|---|---|
| 🟥🟥🟥🟥 Big card | FP32 | 4 bytes | 0.123456 (very exact) |
| 🟥🟥 Medium card | BF16 | 2 bytes | 0.123 (exact enough) |
| 🟥 **Small card** | **FP8** | **1 byte** | 0.12 (a bit rough) |

FP8 is the small card: the same number in less space, a little less exact.

### A compressed photo 📸

A 10 MB photo compressed to 5 MB lost some detail, but your eyes can't see the difference. FP8 is the same: it loses a tiny bit of detail that usually doesn't change the answer.

## The math

### Why the tiny loss doesn't matter

**1. The errors are tiny and cancel out.** Some numbers go a little up, some a little down. Across billions of numbers it mostly evens out.

**2. The top word usually stays on top.**

```
BF16:  "Paris" 0.92   "London" 0.05   "Rome" 0.03
FP8:   "Paris" 0.91   "London" 0.06   "Rome" 0.03
```

The numbers changed a little, but "Paris" still wins. Same answer ✅

### The 2 types of FP8

| Type | Good at | Biggest number | Used for |
|---|---|---|---|
| **E4M3** | more exact | 448 | **Inference** ⭐ |
| E5M2 | bigger numbers | 57,344 | Training |

When people say "FP8 model", they almost always mean **E4M3**. (The names just describe how the 8 bits are split. No need to memorise.)

### FP8 needs a scale too

The biggest E4M3 number is only 448. So, like quantization:

```
scale → divide → store in FP8 → multiply back
```

### FP8 vs INT8 (both 1 byte)

| | INT8 | FP8 |
|---|---|---|
| Stores | whole numbers (-127 to 127) | **decimals** |
| Small numbers like 0.001 | often become 0 ❌ | kept ✅ |
| Giant-number problem | hurts a lot | hurts **less** |

## Inference connection

### 70B model

| Format | Size | Speed |
|---|---|---|
| BF16 | 140 GB | normal |
| **FP8** | **70 GB** | **about 2× faster** 🚀 |

- In **vLLM**, turn it on with `--quantization fp8`.
- Meta released its biggest Llama model (405B) in FP8.

### How do we know FP8 is accurate? Test it

1. Ask the BF16 model 1,000 questions and score it.
2. Ask the FP8 model the **same** questions and score it.
3. Compare:

```
BF16:              score 80.0
FP8:               score 79.6   ← almost the same ✅
INT4 (no groups):  score 70.0   ← too much loss ❌
```

### Which format is "best"?

| Goal | Best choice |
|---|---|
| Highest accuracy, cost doesn't matter | BF16 |
| **Almost the same accuracy, half the cost, faster** | **FP8** ⭐ |
| Smallest model, small quality drop is OK | INT4 (with groups) |

### Quality risk by format

| Format | Risk of worse answers |
|---|---|
| FP8 | Very low ✅ |
| INT8 | Low ✅ |
| INT4 with groups (AWQ / GPTQ) | Small, usually fine 🟡 |
| INT4 without groups | Higher ❌ |
| 2-bit / 3-bit | High ❌ |

When quantization goes wrong, the model gets **dumber** (more mistakes in maths, code and long answers). It isn't a new kind of hallucination.

## Remember

- FP8 = **1-byte decimal**, half of BF16.
- Half the size → **half the memory, faster, cheaper**.
- BF16 is more exact. FP8 is the **best deal**: almost the same answers at half the cost.
- Needs **H100 or newer**.
- **E4M3** for inference ⭐, E5M2 for training.
- Uses a **scale**, like quantization.
- **Always test quality** before using it.
